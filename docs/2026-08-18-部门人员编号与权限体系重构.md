## 一、编号槽位制（8a29ea3 + 2f73952）

### 背景

原实现中员工编号跟随人员，人员离开部门后编号一并带走，新人进入会生成全新编号。

### 变更

**槽位制**：编号属于部门位置，不属于人。

- 人员离开管控部门（MARKET/DIVISION）时，`employeeNo` 强制清空，槽位空出
- 新人进入时分配最小空位编号（`generateNextEmployeeNo` 找最小空号）
- 适用操作：`transfer` 调岗、`setStatus` 禁用、`removeFromDepartment` 移出

**编号格式**

| 部门类型 | 格式 | 示例 |
|---------|------|------|
| MARKET | `{code}{seat:2}` | `MKT0201` |
| DIVISION | `{code}{seat:2}` | `DIV020101` |
| 其他部门 | `{code}{seq:4}` | `HQ0001`, `DEV010001` |

**全部门编号体系**：所有配置了 `code` 的部门都参与编号体系，`deptHasEmployeeNoScheme(code)` 统一判断。非管控部门用 4 位递增序号，无容量上限，人走编号同样归还。

**新增部门短码**

- 新建部门时 `code` 字段必填
- 输入部门名称后自动根据拼音首字母生成建议（如"股东会" → `GDH`）
- 编辑部门时 `code` 只读展示，不可修改

**Seed 数据**

所有部门补充 `code`；种子员工编号更新为新格式；新增 HQ/直属战略单元/督导中心及下属的种子人员。

## 三、部门人数统计修复（78e2e12）

### 问题

`departments.service.ts` 的 `_count.users` 查询条件带了 `employeeNo: { not: null }`，GOVERNANCE/HQ 等无编号部门成员统计为 0，与右侧列表实际人数不符。

### 修复

移除 `employeeNo: { not: null }` 条件，改为只按 `status: 'ACTIVE'` 统计所有在职成员。

## 四、客户来源快照（d06acb1）

### 背景

`Customer.referredBy` 记录的是 User ID，若员工离职后 `employeeNo` 被释放，无法追溯"当时是哪个编号的人带来的"。

### 变更

`Customer` 表新增两个冗余快照字段：

```sql
ALTER TABLE "Customer"
  ADD COLUMN "referrerEmployeeNo" TEXT,
  ADD COLUMN "referrerDepartmentId" TEXT;
```

小程序注册（`POST /public/register`）时同步写入，历史归因不受人员变动影响。

## 五、小程序权限体系（43acce5）

### 背景

原权限逻辑仅靠 `role`（ADMIN/HEAD/MEMBER）判断，市场部 HEAD 无法看到下属事业部客户，且没有只读/可写区分。

### DataScope 模型

新建 `src/common/data-scope.ts`，引入统一的数据作用域概念：

| Scope | 适用用户 | 客户可见范围 | 可写 |
|-------|---------|------------|------|
| `SELF` | 事业部 MEMBER | 仅自己维护的客户 | ✅ |
| `DEPARTMENT` | 事业部 HEAD | 本事业部全部客户 | ✅ |
| `MARKET_TREE` | 市场部人员 | 本市场部 + 下属所有事业部客户 | ✅ |
| `ALL_READONLY` | 发展/服务中心 | 全量客户 | ❌ |
| `ALL_WRITABLE` | 营销中心 HEAD、ADMIN | 全量客户 | ✅ |

### JWT 扩展

`signToken` 增加 `departmentType` 字段，`JwtStrategy.validate` 从 DB 读取并注入 `currentUser`，后续请求无需额外查库判断权限。

### 客户模块重构

- `findAll`：MARKET_TREE 查子事业部 ID 列表后 `departmentId IN [...]`
- `findOne` / `update` / `disable`：改用异步 `checkAccess`，`ALL_READONLY` 写操作返回 403
- `transfer`：去掉 role 硬判断，SELF scope 禁止转移

### 后续扩展

新增数据类型只需调用 `resolveDataScope(currentUser)` 即可复用同一套权限规则。
