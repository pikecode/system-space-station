# 投资客户管理系统 — 项目分析与规划

> 生成日期：2026-07-28
> 背景：面向投资机构的客户-会员-分成管理系统，合伙人通过小程序录入客户、开通会员（入会投资），系统自动按配置比例向多层分成角色分配收益。

---

## 一、企业客户信息字段分析

### 1.1 当前字段

| 字段 | 类型 | 说明 |
|------|------|------|
| creditCode | String? | 统一社会信用代码 |
| industry | String? | 行业 |
| contactName | String? | 联系人姓名 |
| contactPhone | String? | 联系人手机 |

### 1.2 投资背景下的缺失字段

**基本工商信息（尚未采集）**

| 建议字段 | 用途 | 优先级 |
|---------|------|--------|
| legalPerson | 法人代表姓名，签合同必需 | 高 |
| registeredCapital | 注册资本（万元），评估投资能力 | 高 |
| establishedAt | 成立日期，资质审查 | 中 |
| registeredAddress | 注册地址（可与联系地址不同） | 中 |
| businessScope | 经营范围简述，行业研判 | 低 |

**投资合规信息（投资类业务强需求）**

| 建议字段 | 用途 | 优先级 |
|---------|------|--------|
| isAccreditedInvestor | 是否合格投资人（监管要求） | 高 |
| riskTolerance | 风险承受能力（保守/稳健/积极/激进） | 高 |
| investmentExperience | 投资经验年限 | 中 |
| expectedInvestmentAmount | 意向投资金额区间 | 高 |
| bankName | 开户行名称（结算用） | 中 |
| bankAccount | 银行账号（结算用） | 中 |

**个人客户同样缺失的投资信息**

| 建议字段 | 用途 | 优先级 |
|---------|------|--------|
| idCardMasked | 身份证号（脱敏存储，合同/合规） | 高 |
| annualIncome | 年收入区间，合格投资人认定参考 | 中 |
| netAssets | 净资产区间，合格投资人认定参考 | 中 |
| isAccreditedInvestor | 是否合格投资人 | 高 |
| riskTolerance | 风险承受能力 | 高 |
| investmentExperience | 投资经验年限 | 中 |
| expectedInvestmentAmount | 意向投资金额 | 高 |

### 1.3 结论

当前企业字段仅覆盖基础工商标识（信用代码、行业、联系人），**缺少所有投资合规相关信息**。建议在下一版本中分两批补充：
- **第一批（必须）**：legalPerson、isAccreditedInvestor、riskTolerance、expectedInvestmentAmount
- **第二批（重要）**：registeredCapital、bankName、bankAccount、idCardMasked、annualIncome/netAssets

## 三、待规划功能

### 3.1 高优先级 — 业务核心补全

**A. 投资合规信息采集**
- 客户画像补充：风险承受能力、合格投资人认定、意向投资额
- 支持在注册页（客户自填）和客户详情（合伙人录入）两个入口采集
- 后端 schema 新增相关字段，前端表单新增「投资意向」tab

**B. 会员合同管理**
- 会员开通时上传合同附件（PDF/图片）
- 支持合同编号、签署日期记录
- 会员详情页显示合同附件链接

**C. 结算报表导出**
- 按结算周期导出 Excel：分成明细、汇总
- 个人分成对账单
- 目前 API 有 overview 端点，但缺导出功能

**D. 消息通知**
- 会员申请提交后通知审批人（企业微信/短信）
- 审批结果通知提交人
- 结算完成通知收款人

### 3.2 中优先级 — 提升运营效率

**E. 客户跟进记录（CRM）**
- 跟进日志：时间、方式（电话/微信/面谈）、内容、下次跟进日期
- 支持在客户详情页添加跟进记录
- 提醒功能（下次跟进日期到期）

**F. 风险评估问卷**
- 独立的风险评估流程（6-10 题标准化问卷）
- 自动计算风险等级并写入客户档案
- 与合格投资人认定挂钩

**G. 会员到期提醒**
- 提前 30/15/7 天提醒合伙人对应客户会员即将到期
- 支持续费操作入口

**H. 数据看板（Web 端）**
- 客户转化漏斗：登记→开会员→续费
- 各部门/合伙人业绩排名
- 分成收入趋势图

### 3.3 低优先级 — 完善度提升

**I. 客户去重与合并**
- 按手机号/身份证检测重复客户
- 支持手动合并操作

**J. 批量操作**
- 批量导入客户（Excel 模板）
- 批量转移客户归属

**K. 小程序审批流完善**
- 当前审批页面（approvals/index）已有页面文件但功能程度待确认
- 支持在小程序内完成会员审批操作

## 四、技术债务与待修复问题

| 问题 | 影响 | 建议处理 |
|------|------|---------|
| `idCardEncrypted`/`idCardHash`/`idCardMasked` 字段已在 User 上，但 Customer 无身份证字段 | 合规风险，客户无法做 KYC | 迁移或在 Customer 上新增同样结构 |
| CommissionRecord.receiverRole 包含 REFERRAL 但分成配置无对应 referralRatio 实际生效路径 | 转介绍分成逻辑可能不完整 | 核查分成计算逻辑 |
| Web 端实现程度不明，是否与 API 完全对齐未知 | 管理员无法使用 Web 后台 | 盘点 Web 已实现页面 |
| 小程序 approvals 页面存在但功能未确认 | 审批流程缺口 | 确认并补全 |

---

## 五、建议开发顺序

```
阶段一（1-2周）：合规与信息完整性
  ├── 客户画像补充字段（schema + API + 小程序表单新增投资意向 tab）
  └── 会员合同附件上传

阶段二（2-3周）：通知与报表
  ├── 审批通知（企微/短信）
  ├── 结算报表导出
  └── 会员到期提醒

阶段三（3-4周）：CRM 深度
  ├── 客户跟进记录
  ├── 风险评估问卷
  └── Web 数据看板

阶段四（持续）：运营工具
  ├── 批量导入/导出
  ├── 客户去重
  └── 小程序审批流完善
```
