# 客户归属分享码重构设计

**日期：** 2026-07-27  
**状态：** 待实现  
**范围：** 后端 customers 模块、auth 模块，小程序客户录入页

---

## 一、背景与目标

### 现有问题

当前客户创建逻辑：`assignedTo` / `departmentId` 从**登录用户**自动派生。导致：

- 管理员无法录入客户（ADMIN 没有部门）
- 无法代录（A 录入的客户只能归属 A，无法归属 B）
- 客户归属逻辑与"谁点提交"强耦合，不符合业务实际

### 业务规则（确认）

1. 营销中心（MARKET / DIVISION 类型）用户拥有唯一分享码（`shareCode`）
2. 每个客户录入**必须携带一个分享码**，客户归属完全由分享码决定
3. 任何人（含管理员）都可以代录客户，只要分享码正确
4. 公开注册（扫码落地页）与内部录入共用同一套归属逻辑

---

## 二、数据模型

无需 schema 变更，现有字段已够用：

| 字段 | 说明 |
|------|------|
| `Customer.assignedTo` | = shareCode 对应用户的 id |
| `Customer.departmentId` | = shareCode 对应用户的 departmentId |
| `Customer.referredBy` | = shareCode 对应用户的 id（同 assignedTo） |
| `Customer.source` | 有邀请码时默认 `REFERRAL`，手动录入时调用方指定 |
| `Customer.createdBy` | = 实际登录并提交请求的用户 id（审计用途） |

---

## 三、接口变更

### 3.1 `POST /customers`（内部录入，需登录）

**新增字段：**

```ts
shareCode: string  // 必填，归属依据
```

**处理逻辑变更：**

```
原逻辑：
  assignedTo  = currentUser.id
  departmentId = currentUser.departmentId
  referredBy  = 无

新逻辑：
  owner = await prisma.user.findUnique({ where: { shareCode } })
  if (!owner) → 400 分享码无效
  if (owner.status !== ACTIVE) → 400 分享码用户已停用
  if (!owner.departmentId) → 400 分享码用户未分配部门
  assignedTo   = owner.id
  departmentId = owner.departmentId
  referredBy   = owner.id
  createdBy    = currentUser.id（保留，用于审计）
```

**移除校验：**

- 删除 `if (!currentUser.departmentId) throw BadRequestException`（不再依赖登录用户部门）

### 3.2 `GET /auth/me`（小程序自动填充分享码）

**新增返回字段：** `shareCode: string | null`

方便小程序在客户录入时预填当前登录用户的分享码。

### 3.3 `POST /public/register`（已实现，无变更）

已使用 shareCode 派生归属，逻辑一致，无需修改。

---

## 四、小程序变更

### 4.1 Auth Store

`me` 接口返回后，将 `shareCode` 存入 store，方便各页面取用。

### 4.2 客户录入页（`pages/customers/index` 或创建入口）

- 表单新增**分享码**输入字段（必填）
- 默认预填当前登录用户的 `shareCode`（若有）
- 允许手动修改（代录场景）
- 提交时将 `shareCode` 传给 `POST /customers`

## 六、边界情况

| 情况 | 处理方式 |
|------|----------|
| shareCode 不存在 | 400 分享码无效 |
| shareCode 对应用户已离职/停用 | 400 分享码用户已停用 |
| shareCode 对应用户没有部门 | 400 分享码用户未分配部门 |
| 同一手机号已存在客户 | 由现有唯一性校验处理（如有） |
| 管理员录入 | 正常，只要提供有效 shareCode |
