## 二、权限矩阵

### 2.1 客户数据

| 用户所在部门 | 角色 | 可查看范围 | 可修改/维护 |
|------------|------|----------|------------|
| DIVISION（事业部） | MEMBER | 仅自己维护的客户 | 自己的客户 |
| DIVISION（事业部） | HEAD | 本事业部全部客户 | 本事业部客户 |
| MARKET（市场部） | HEAD / MEMBER | 本市场部 + 下属所有事业部的客户 | 本市场部及下属事业部客户 |
| CENTER — 发展中心 | 任意 | 全量客户 | ❌ 只读 |
| CENTER — 服务中心 | 任意 | 全量客户 | ❌ 只读 |
| CENTER — 营销中心 | HEAD | 全量客户 | ✅ 可修改下级（市场部、事业部）的客户 |
| CENTER — 营销中心 | MEMBER | 全量客户 | ❌ 只读（仅查看） |

> 说明：市场部没有普通成员（MEMBER），市场部人员均为管理角色，可见范围包含自己及下属事业部的所有客户。

### 2.2 人员数据

| 用户所在部门 | 可查看成员范围 |
|------------|--------------|
| DIVISION | 本事业部成员 |
| MARKET | 本市场部成员 + 下属所有事业部成员 |
| CENTER（发展/服务/营销） | 全量在职成员（只读） |

## 三、数据作用域（DataScope）模型

所有数据权限统一归一到 `DataScope`，新增数据类型时复用同一套规则。

```
DataScope 枚举：
  SELF          - 只看自己（userId 过滤）
  DEPARTMENT    - 本部门（departmentId 过滤）
  MARKET_TREE   - 市场部 + 下属所有事业部（departmentId IN 列表）
  ALL_READONLY  - 全量只读
  ALL_WRITABLE  - 全量可读可写（营销中心 HEAD）
```

### 作用域计算规则

```
DIVISION MEMBER  → SELF
DIVISION HEAD    → DEPARTMENT(divisionDeptId)
MARKET 任意角色  → MARKET_TREE(marketDeptId)
发展中心 任意    → ALL_READONLY
服务中心 任意    → ALL_READONLY
营销中心 MEMBER  → ALL_READONLY
营销中心 HEAD    → ALL_WRITABLE
```

## 四、JWT 扩展

当前 JWT payload：
```json
{ "sub": "userId", "role": "MEMBER", "departmentId": "...", "authVersion": 1 }
```

需新增 `deptType` 字段，登录时从数据库读取写入 token，避免每次请求查库：

```json
{ "sub": "userId", "role": "MEMBER", "departmentId": "...", "deptType": "DIVISION", "authVersion": 1 }
```

## 五、实现要点

### 5.1 后端

1. **`auth.service.ts`**：miniApp 登录时在 JWT payload 中增加 `deptType`
2. **`common/data-scope.ts`**（新建）：`resolveDataScope(currentUser)` 函数，输入 `{ role, departmentId, deptType }`，返回 `DataScope`
3. **`customers.service.ts`**：
   - `findAll` / `findOne`：替换现有 role 判断逻辑，改用 `resolveDataScope`
   - `update` / `transfer`：新增写权限校验（`ALL_READONLY` 返回 403）
4. **`MARKET_TREE` 实现**：查询市场部下所有事业部 ID，`departmentId IN [marketDeptId, div1Id, div2Id, ...]`

### 5.2 前端（小程序）

- 登录态存储增加 `deptType` 字段
- 根据 `DataScope` 控制 UI 展示：只读用户隐藏编辑/转移按钮
- 市场部人员的客户列表需要展示"所属事业部"列，方便区分
